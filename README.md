# Euler-resolve

A Claude Code / Claude skill plugin marketplace for visual and web design judgment — built to catch the specific, nameable mistakes that make work look accidental, inaccessible, or AI-generated by default.

## The Problems

Two distinct but related failures, one per plugin in this marketplace:

> Most visual work fails not because the details are wrong, but because the structural decisions — proportion, focal point, hierarchy — were never made explicitly. Everything gets decided at once, at the same level, which is why unguided work tends to come out centered, evenly-weighted, and flat by default.

> By 2026, a large share of AI-generated web design has converged on the same handful of defaults — a purple-to-blue gradient hero, glassmorphism applied everywhere instead of on one element, a bento grid used as furniture, floating cards with an identical soft shadow, a giant centered headline in Inter above two lines of vague aspiration. This isn't a vague feeling anymore; design communities routinely name the exact patterns. It happens because those patterns are the statistical average of the training data — the safest, most inoffensive choice — not because anyone decided they were right for a specific product.

## The Solution

Two plugins, each addressing one half:

| Plugin | Addresses |
|---|---|
| **euler-resolve** | Composition made by accident — no deliberate proportion, focal point, hierarchy, or perceptual check, for any visual/artistic medium |
| **web-design-system** | Web/product color built ad hoc instead of as an engineered system, and the specific 2026 AI-slop defaults (gradient hero, glass-everywhere, bento-by-default, floating cards, Inter-and-giant-centered-headline, vague copy) shipping unexamined |

## euler-resolve

A structural framework for visual/artistic work of any kind (painting, drawing, illustration, UI/web design, branding, editorial layout), layered in the order that matters — **structure before surface**:

| Layer | Covers |
|---|---|
| **Mathematical foundations** | Proportion systems (golden ratio, root rectangles), grids, symmetry groups, perspective, color-wheel relationships, WCAG contrast |
| **Perception and biology** | Gestalt grouping, how the eye and fovea actually work, contrast sensitivity, pre-attentive processing, scan patterns, depth cues |
| **Artistic principles** | Balance, emphasis, rhythm, proportion, negative space, hierarchy |
| **Anti-patterns ("negative design")** | A checklist of the specific, recurring mistakes that make visual work look generic, flat, or broken, with the reason each happens and how to fix it |

Reference files live at `plugins/euler-resolve/skills/euler-resolve/references/`.

## web-design-system

Color system engineering for web/product UI, paired with a forceful, mandatory anti-slop audit:

| Part | Covers |
|---|---|
| **Color systems** | Color spaces (why OKLCH over HSL for scale/gradient work), semantic/functional tokens, scale construction (Tailwind-style, Radix-style, Material HCT), harmony for interfaces, gradients |
| **Accessible contrast and dark mode** | Real WCAG 2.x numbers, the current (unsettled) APCA/WCAG3 status stated honestly, colorblind-safety, focus-state contrast, dark mode as a genuine redesign rather than an inversion |
| **Anti-slop: visual and layout** | 12 named, currently-overused AI-generated web patterns (gradient hero, glass-as-default, bento-as-default, floating shadow cards, and more) — each must be absent or a stated decision |
| **Anti-slop: typography and copy** | 8 named patterns (giant centered headline, gradient text, uniform weight, generic marketing voice, and more) — same rule |
| **Pre-ship verification** | The final gate: contrast, colorblind, dark-mode, motion, full anti-slop pass, and a real-context check before anything is called finished |

Reference files live at `plugins/web-design-system/skills/web-design-system/references/`.

## Install

**Claude Code / Claude Cowork (plugin marketplace):**
```
/plugin marketplace add trinityman-hash/Euler-resolve
/plugin install euler-resolve@euler-resolve
/plugin install web-design-system@euler-resolve
```

**Manual (claude.ai Skills):**
Download the relevant `plugins/<name>/skills/<name>` folder and add it as a skill in Claude (Settings → Capabilities → Skills). The two plugins are independent — install one, both, or neither.

## How These Relate

`euler-resolve` is medium-agnostic — it applies to a painting exactly as much as a web page. `web-design-system` is the web/product-specific layer on top of it for two things euler-resolve doesn't cover in depth: engineered color systems, and the specific patterns currently overused in AI-generated web output. Use both together for web/product work; `euler-resolve` alone for other visual/artistic mediums.

Neither plugin duplicates implementation guidance that already exists elsewhere. When a task requires writing actual code, both defer to `karpathy-guidelines` for how to write it (minimum code, surgical edits, no speculative config) and, in Claude.ai's environment, to `frontend-design` for the concrete CSS tokens and constraints actually available there.

## On the Anti-Slop Checklists

The negative-design lists in `web-design-system` name patterns that are specifically overused **as of 2026** — sourced from current design-community criticism, CSS/browser-support tracking, and WCAG status checks at the time this was written, not invented from assumption. They are deliberately dated, not timeless law: what's an unmotivated default today may be a genuinely correct choice for a specific brief tomorrow, or may already have shifted by the time this is read. The requirement is that using one of these patterns is a stated decision tied to the actual brief, not something that shipped because it was the statistically safest output.

If contrast/WCAG compliance is load-bearing for a real project, verify current standards directly — standards bodies and browser support move faster than any static reference file can track.

## Tradeoff Note

Both plugins bias toward deliberate decisions over speed — running a five-layer check on a genuine one-off throwaway prototype is more ceremony than it needs. For trivial or disposable work, use judgment; the goal is catching costly, invisible defaults on real, user-facing work, not adding process to everything.
